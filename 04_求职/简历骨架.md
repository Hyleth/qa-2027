## 三、项目经历（两个，必须带数字）

### 项目一：AI 应用质量评测体系（个人项目 · Python / pytest / LLM API）

- 针对大模型问答类应用设计 **6 类**评测集（事实准确性 / 边界规则 / 拒答 / 提示词注入 / 幻觉 / 多轮上下文），共 **40 条**，每条定义独立判定标准
- 实现「规则判定 + LLM-as-Judge」双判定器：规则层覆盖关键词与结构，模型裁判层覆盖语义质量，两者不一致的样本转人工抽检 —— 实测一致率 **32.5%**，即人工只需看 1/3 的样本
- 量化四个核心指标：事实准确率 **100%**、幻觉率 **50%**、拒答准确率 **85.7%**、注入抵抗率 **25%**，定位出 **6 类**可绕过场景
- 建立 **10 条** Prompt Injection 攻击样本库，覆盖指令覆盖、角色扮演、编码绕过、权限伪造四类

> **面试会追问**：32.5% 这个数怎么来的？→ 40 条里两个判定器结论一致的有 13 条。
> 25% 注入抵抗率说明什么？→ 8 条攻击顶住 2 条，产品对正常用户友好、对恶意输入不设防。

### 项目二：接口自动化测试框架（个人项目 · pytest / YAML / JSON Schema / GitHub Actions）

- 基于 pytest 分层框架：用例数据 YAML 驱动、响应体用 JSON Schema 守契约、token 走 fixture 依赖注入
- 覆盖登录 / 鉴权 / 订单 / 退款 **4 个模块**共 **19 条**用例，单轮执行 **2.5 秒**
- 用 `xfail(strict=True)` 管理已知缺陷：缺陷修复后用例自动转红提示摘除标记，避免"测了没人看"的失效用例
- 接入 GitHub Actions，每次提交自动回归

> **面试会追问**：为什么 fixture 用 session 级？→ 起服务贵且要复用；客户端必须函数级，否则 token 互相覆盖。
> JSON Schema 的 pattern 有什么用？→ 守"金额必须是 199.00 这种字符串"的约定，防止开发改成浮点。
