# 2026-11-13 学习笔记 · HTTP 客户端封装

> 一句话主题：`http_client.py` 把"发 HTTP 请求"这件事收拢成一个类，向上被 fixture 调用、被用例使用，向下调用 requests 库把请求发给 mock 服务。

---

## 一、这个文件在干什么

`core/http_client.py`（90 行）只做三件事：

1. **统一 base_url** —— 用例里只写 `/api/orders/O1001`，不写完整地址，换环境只改一处
2. **自动带 token** —— 不用每条用例手写 headers
3. **统一返回** —— 用例拿到的是 response 对象，断言直接写 `resp.json()["code"]`

**"封装"的唯一意义**：三条用例时和直接用 requests 没区别；五十条时，每条都重复写 headers、拼 URL、记 base_url，改一处要改五十处。封装就是把重复的东西收拢到一处。

## 二、类 + 构造方法（今天第一次见）

W1 只写过函数（独立 `def`），今天第一次见类（`class`）。

```python
class ApiClient:
    def __init__(self, base_url: str, timeout: float = 5.0) -> None:
        self.base_url = base_url.rstrip("/")
        self.timeout = timeout
        self.session = requests.Session()
        self.token: str | None = None
```

一句话理解：

> **类是一个"带状态的工具箱"，`self` 就是"这个工具箱自己"。** `self.token` 是这个工具箱里存的 token，`self.base_url` 是它记的地址。

`__init__` 是"造一个工具箱时先做的初始化"——把 base_url、session、token 先放进去。之后每次调 `client.post(...)`，都是"从这个工具箱拿工具、用它的状态"。

**关键认知**：token 能"自动带"，就是因为存进了 `self.token`，能被后续方法反复用。

## 三、三个新写法（今天问的）

### 1. `rstrip("/")`

```python
self.base_url = base_url.rstrip("/")
```

去掉字符串**末尾**的 `/`（`r` = right，`strip` = 剥掉）。是 `str.strip()` 的兄弟，`strip()` 去两头，`rstrip()` 只去右边。

**为什么需要**：`_url()` 里是 `f"{self.base_url}{path}"`，如果 base_url 末尾带 `/`，拼出来就是 `...8000//api/login`（两个斜杠），接口就错了。所以先剥掉，保证只有 path 自己带的那个 `/`。

### 2. 类型标注 `-> None`、`-> str`

```python
def __init__(self, ...) -> None:   # 返回 None，即不返回东西
def _url(self, path: str) -> str:  # 参数是 str，返回也是 str
def pretty(self, resp) -> str:     # 返回一个字符串
```

`-> xxx` 是**"这个函数返回什么类型"的标注**。**完全不改变程序运行**，删掉照样跑。

作用只有两个：① 编辑器能提示（传错类型会提醒）；② 读代码的人一眼知道函数"吃什么、吐什么"。

**现在阶段：看得懂就行，不用主动写。**

### 3. `self.token: str | None = None`

```python
self.token: str | None = None
```

三段拆开：

| 片段 | 意思 |
|---|---|
| `self.token` | 给对象建一个叫 token 的属性 |
| `: str \| None` | 类型标注：token 要么是字符串，要么是 None |
| `= None` | 初始值是 None（还没登录，没 token） |

`str | None` 是"两种类型二选一"。`login()` 成功后 `self.token = ...` 把 None 换成真 token。

而 `_headers()` 里 `if self.token:` 正是利用这点——None 是"假"，没登录不加 Authorization；登录后是真字符串，"真"，就加上。

## 四、请求是怎么流经整个框架的

一次测试运行 = 三个环节接力：**准备(fixture) → 发请求(http_client) → 断言(assert)**。

```
pytest 启动
  │
  ├─ 读 conftest.py ──► 造好 base_url、client、alice 等 fixture（准备）
  │
  ├─ 读 test_login.py ──► 发现用例，parametrize 展开 5 条
  │
  └─ 每条用例执行：
       1. 调 client.post(...)              ← 进 http_client.py
       2.   post → request                  ← 快捷方法转真正方法
       3.   _url 拼地址 + _headers 带 token + session.request 发请求
       4.   ──► mock_server.py 收到请求、返回响应
       5.   响应存进 resp，回到用例
       6. assert 比对 status_code + body["code"]
```

### 各文件的分工

| 文件 | 角色 | 类比 |
|---|---|---|
| `conftest.py` | 准备"工具"（起服务、造 client、登录） | 测试前的手工准备 |
| `http_client.py` | 封装"发请求" | 你的 Postman |
| `test_login.py` | 写"测什么、怎么比" | 用例 + 断言 |
| `mock_server.py` | 假装后端，返回假数据 | 开发起好的服务 |
| `cases.yaml` | 存"输入什么、期望什么" | 测试数据 |

### http_client 内部调用链

`client.post(...)` 进去后：

1. `post` → 转给 `request`，塞进 `"POST"`
2. `request` → 处理 token（`with_auth=False` 时临时清掉、`finally` 恢复），再调 `self.session.request(...)`
3. `self._url(path)` → 拼完整地址
4. `self._headers()` → 生成带 token 的请求头
5. `self.session.request` → 真正用 requests 库发出请求

## 五、`with_auth=False` 的用途

```python
def request(self, method, path, *, json_body=None, headers=None, with_auth=True):
    saved = self.token
    if not with_auth:
        self.token = None          # 暂时清掉，假装"没登录"
    try:
        return self.session.request(...)
    finally:
        self.token = saved         # 请求完恢复
```

**为什么需要**：登录接口本身不能带 token（还没登录，哪来的 token？）。

**巧妙之处**：请求前临时清掉、请求后 `finally` 恢复，这样"测没带 token 会被拦"的用例和正常用例可以共用同一个 client，不会互相污染。

## 六、两层断言（今天的合格线）

```python
assert resp.status_code == case["expect"]["status"]   # 第一层：HTTP 状态码（网络层）
body = resp.json()
assert body["code"] == case["expect"]["code"]         # 第二层：业务码（业务层）
```

**为什么不能只断言 `status_code == 200`**：很多系统业务出错也返 200（比如"余额不足"这种业务失败），靠 body 里的 `code` 区分到底成功还是失败。

- `resp.status_code`：HTTP 状态码（200/400/401...）
- `resp.json()`：把返回的 JSON 字符串转成 dict，再取 `["code"]`
