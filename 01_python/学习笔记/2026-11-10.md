# 学习笔记 · 2026-11-10

> 来源：W2 D1 跑通 19 条用例 + 追问 pytest 发现机制
> 主题：**pytest 是怎么"找到用例"的（用例发现机制）**

---

## 一、一句话总结

pytest 启动后，先读 `pytest.ini` 拿到"去哪找"，然后按 **目录 → 文件 → 类 → 函数** 四层去收集用例，收集过程中自动导入 `conftest.py` 拿到共用的 fixture。

---

## 二、发现顺序（四层）

```
① 目录   ← 由 pytest.ini 的 testpaths 决定（本项目 = tests）
② 文件   ← 文件名以 test_ 开头，或 _test 结尾（.py）
③ 类     ← 类名以 Test 开头，且类里没有 __init__ 方法
④ 函数   ← 函数名以 test_ 开头
```

每层的关键规则：

| 层 | 规则 | 本项目的例子 |
|---|---|---|
| 目录 | `testpaths = tests`，只扫这里 | 只找 `02_api/tests/` |
| 文件 | `test_*.py` 或 `*_test.py` | `test_login.py`、`test_orders.py` |
| 类 | `Test` 开头 + 无 `__init__` | 本项目没用到类，全是裸函数 |
| 函数 | `test_` 开头 | `test_login_by_data`、`test_query_own_order_success` |

---

## 三、三个文件各干什么（别搞混角色）

| 文件 | 干什么 | 谁去读它 |
|---|---|---|
| `pytest.ini` | 告诉 pytest **去哪找** + 全局选项（`-v` 等） | pytest 启动时读 |
| `conftest.py` | 放**共用的 fixture**，不产生用例、不产生输出 | pytest **自动导入**，不用手动 import |
| `test_*.py` | 真正装用例的文件 | pytest 收集时读 |

**关键区分**：`conftest.py` 不是"被发现"，是"被自动导入"。它自己不产生任何输出，所以单独跑它什么都没发生是正常的。

---

## 四、两个容易踩的坑

1. **`testpaths` 会限制扫描范围**：直接 `pytest` 扫不到 `tests/` 之外的目录。
   11/19 建 `my_cases/` 时，要显式写 `pytest my_cases`，不能只敲 `pytest`。
2. **类有 `__init__` 会被跳过**：如果写类来装用例，类里不能有 `__init__` 方法，
   pytest 会认为它是普通类、不是测试类。

---

## 五、本项目的实际对应

- `pytest.ini` → `testpaths = tests`，所以 pytest 只去 `02_api/tests/` 找
- `tests/` 下三个文件：`test_login.py`（登录）、`test_orders.py`（订单）、`test_refund.py`（退款）
- 19 条用例全是**裸函数**（`test_` 开头），没有套类
- `conftest.py` 里放了 4 个 fixture：`base_url`(session) → `client`(function) → `alice`/`bob`

---

## 六、我之前的理解 vs 修正

| 我的理解 | 修正 / 补充 |
|---|---|
| pytest 先读 ini，再读 conftest，再找文件 | conftest 是"收集过程中自动导入"，不是线性读完再找 |
| 找到 `Test` 开头的类 | 类还要满足"无 `__init__`"，且类不是必须的（裸函数也行） |
| （漏了目录层） | 补上：顺序是 目录 → 文件 → 类 → 函数，目录由 testpaths 定 |
