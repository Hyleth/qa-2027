## 先看这个：接口自动化学到什么程度算够（你的第 3 个问题）

**结论：学到 L4，不用到 L5。** 每一级都有明确的自评方法，你随时能知道自己站在哪。

| 级别 | 标准 | 怎么自评 | 时间 |
|---|---|---|---|
| **L0** | 会用 Postman 手动调接口 | 你 2021 年就能 | 已有 |
| **L1 能跑** | 命令跑出结果，看懂红绿和失败原因 | `pytest -q` 出 19 条，能说出哪 2 条是 xfail、为什么 | W2 第 1 天 |
| **L2 能改** | 只改 YAML 加用例，不动代码 | 加 3 条用例，`pytest` 仍绿 | W2 末 |
| **L3 能写** | 自己写 5 条用例（正常 / 参数化 / 鉴权 / Schema / 边界） | 新建目录能独立跑出 5 条全绿 | W3 末 |
| **L4 能搭** | 从零建一个最小框架（conftest + client + 用例 + 配置） | Gate 1 闭卷：空目录 2 小时搭出能跑的 | W4 末 |
| **L5 能设计** | 对一个真实系统设计 30 条用例 + 分层策略 + 数据管理 | 需要真实业务环境 | 入职后 |

**为什么停在这里：**

- **L3 是市场及格线**——JD 写"能独立编写接口自动化用例"就是这个
- **L4 是你 15K 的底气**——面试官问"你的框架怎么分层的"，L4 的人能画出来并解释每层为什么这么切
- **L5 在这个阶段学不到**，因为它需要的不是技术，是"一套真实在跑的业务 + 半年以上的维护经验"。**硬造出来的 L5，面试一问就露**

**"能讲清"的具体标准**（面试的原话级要求，不是背定义）：

| 概念 | 你该能说出的话 |
|---|---|
| fixture | "它是有作用域的预备动作。起服务用 session 级因为贵；客户端用 function 级因为它带 token，共用会串" |
| conftest | "放共享 fixture 的地方，pytest 自动加载，不用 import" |
| parametrize | "一份代码跑多组数据。5 条登录用例只写 1 个函数，加用例只改 YAML" |
| 数据驱动 | "测什么和怎么测分开。用例表别人能 review，改数据不改代码" |
| xfail | "已知 bug 的标记。strict 模式下修好了会转红，逼你摘标记，避免用例常年挂着没人看" |

**说不出来 = 没学会**，回去把 `02_api` 对应的那几行代码重读一遍。

## W1–W4 结束时你该能说出的话

面试时会问的问题，现在就要能用大白话回答。答不出来说明那周白过了。

| 问题 | 答案要点 |
|---|---|
| 你接口自动化怎么分层？ | 数据层（YAML）/ 客户端层（封装 requests）/ 用例层（只写断言）/ 配置层（conftest） |
| 为什么断言不能只断 200？ | 业务错误常返 200，要看 body 里的 code |
| fixture 比全局变量好在哪？ | 依赖可见、能单条跑、顺序由依赖决定、有清理机会 |
| 用例互相干扰怎么办？ | 隔离数据（每条用自己的数据）+ fixture 用 function 级 |
| 已知 bug 怎么管？ | `xfail(strict=True)`，修好后自动转红逼你摘标记 |
| 金额怎么断言？ | `Decimal` 或格式化字符串，不用 float |
| 加一条用例要改几处？ | 只改 YAML 一处（数据驱动的标志） |
