## 每周怎么过

**只有 3 个必做项。** 三个都完成，这周就算过关；没完成的不要带到下周，直接降级或砍掉。

- 每天 2–3 小时：10 分钟回忆昨天 → 20 分钟看资料 → 80 分钟写代码 → 20 分钟跑通并提交
- 每天必须有一个 commit。不是为了好看，是 commit 是唯一客观的进度证据
- 一周留一天完全不动，防止第 6 周崩掉

**每天早上打开 `01_执行手册/` 里对应周次的逐日表，找到今天的日期，照着做。**

## 关于提交历史

建议按这个节奏推，别一次性把所有东西堆上去：

```
第 1 次  只推 学习计划.md / README.md / 进度看板.html / .gitignore / requirements.txt
W1 起    每天写什么提交什么，commit message 用 feat: / fix: / test: / docs: 开头
```

原因很实际：面试官会看 commit 曲线。第一天 5000 行、之后每天 20 行，
和每天稳定 30–80 行，是两种完全不同的观感。**后者才是"我真的在学"的证据。**

`01_python/`、`02_api/`、`03_llm_eval/` 这几个是练习用的教材骨架，
推到仓库没问题，但要在 README 里说清"这些是练习项目，我在其上做了哪些改造"。

## 一句提醒

这份计划的核心不是"学会多少技术"，是**把你 9 年的业务判断力，翻译成 AI 时代能用的形式**。

AI 能在 10 秒内生成 40 条用例，但它判断不出哪 15 条执行不了、哪个场景漏了并发。
「评测集设计」这个能力，本质就是用例设计 —— 你早就会，只是换了对象。
